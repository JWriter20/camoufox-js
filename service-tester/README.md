# Camoufox-JS Service Tests

End-to-end antibot-detection tests that verify a built camoufox-js (and
the matching camoufox browser binary) produces an A-grade stealth surface
under real proxies. Self-contained: nothing in this directory reaches into
the camoufox sibling repo at runtime — the antibot checks are vendored
into `src/checks/` and bundled at runtime via esbuild.

This is the camoufox-js port of [camoufox/service-tester](../../camoufox/service-tester/README.md).
Same checks, same grading thresholds, same certificate format.

## Prerequisites

- Node.js ≥ 20
- At least one proxy in `proxies.txt`
- The camoufox browser binary (auto-downloaded on first run)

## Quick Start

```bash
# 1. Add your proxies (see format below)
cp proxies.txt.example proxies.txt
$EDITOR proxies.txt

# 2. Run — the script handles install/build/binary-fetch automatically
./run_tests.sh
```

`run_tests.sh` will:
1. `pnpm install` + `pnpm build` in the parent camoufox-js package (if `dist/` missing).
2. `pnpm install` and `pnpm build` here (compiles TS, bundles checks).
3. Fetch the camoufox browser binary into `~/.cache/camoufox-v*/` if absent.
4. Run the full test suite.

## Proxies

Each profile gets its own proxy. The WebRTC IP is auto-derived by camoufox-js
from the proxy server (via `geoip: true`). Format is identical to the python
service-tester so a single `proxies.txt` is interchangeable.

```
user:pass@domain:port
```

Blank lines and `#`-comments are ignored. Round-robin across profiles.

## Manual Setup

```bash
# Build the parent camoufox-js package
(cd .. && pnpm install && pnpm build)

# Install + build this package
pnpm install
pnpm build

# Run
node dist/run_tests.js [options]
```

## Options

```
./run_tests.sh [options]
node dist/run_tests.js [options]

  --profile-count N       Number of profiles to test (1-6, default: 6)
  --headful               Run with visible browser window
  --proxies PATH          Path to proxies file (default: proxies.txt)
  --secret KEY            HMAC signing key for the certificate
  --save-cert PATH        Save certificate text to a file
  --no-cert               Skip certificate generation
  --ff-version N          Pin Firefox/Camoufox major version
```

## What It Tests

`profile-count` browser instances run **simultaneously** (default: 6 — three
macOS profiles, three Linux profiles), each with:

- A unique fingerprint generated by camoufox-js's `fingerprint-generator`
  (firefox-only, navigator/screen/WebGL/fonts/voices/audio/canvas seeds).
- Its own proxy, with WebRTC ICE candidates spoofed to the proxy's IP via
  camoufox-js's `geoip: true` launch flag.
- The antibot checks bundle from `src/checks/` (vendored from
  camoufox/build-tester at port time; identical to the python harness).

Each profile is scored across these categories:

| Category | What it checks |
|---|---|
| Automation Detection | Playwright/CDP artefacts |
| JS Engine | V8 vs SpiderMonkey signals |
| Lie Detection | Inconsistent property overrides |
| Firefox APIs | Firefox-specific API presence |
| Cross-Signal | Consistency across navigator, screen, etc. |
| CSS Fingerprint | CSS rendering fingerprint |
| Canvas Noise | Canvas hash uniqueness and stability |
| WebGL Render | WebGL rendering hash |
| Audio Integrity | AudioContext fingerprint |
| Font Platform | OS-consistent font availability |
| Speech Voices | Voice list matches declared OS |
| WebRTC | IP matches proxy server address |
| Stability | Fingerprint stable over time with other contexts open |
| Headless Detection | No headless mode signals |

## Architectural difference vs. python

camoufox-py's `service-tester/` runs **per-context** fingerprints inside a
**single** browser instance using `AsyncNewContext` (the
`feat/cloverlabs-context-fingerprint` upstream feature).

camoufox-js's `master` doesn't ship per-context fingerprinting yet —
fingerprints are applied at process launch via `CAMOU_CONFIG`. This harness
spins up N independent `Camoufox()` instances in parallel instead. End
result for the validator is equivalent: N distinct, simultaneous
fingerprinted browsers running the same checks. Grade thresholds, JSON
shape, and certificate signature format are identical.

Once the [`feat/cloverlabs-context-fingerprint`](https://github.com/JWriter20/camoufox-js/tree/feat/cloverlabs-context-fingerprint)
branch lands on master we'll switch this harness to per-context, dropping
process-spawn cost.

## Interpreting Results

| Grade | Meaning |
|---|---|
| **A** | All checks pass |
| **B** | 1–2 failures (minor) |
| **C** | 3–5 failures |
| **D** | 6–10 failures |
| **F** | 11+ failures |

A grade of **A or B** exits with code `0`. Anything worse exits with code `1`.

## Failure Triage

If a check fails, **fix it in the camoufox-js package** (`../src/`), not in
the test. The test is intentionally a black-box validator — it only uses
the public `Camoufox()` API and trusts camoufox-js to produce correct
fingerprints.

If a stealth divergence is *by design* (e.g. `navigator.webdriver=false`),
the corresponding check in `src/checks/` is the place to update — the
checks bundle is the camoufox-js view of "what stealth correctness looks
like", and it should track real consumer expectations.
